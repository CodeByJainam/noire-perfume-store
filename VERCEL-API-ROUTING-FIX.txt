NOIRÉ – Vercel API routing fix

What changed
- Removed api/[...path].js and api/auth/[...path].js. Those filenames were relying on Next.js-style catch-all routing, which is not supported the same way by plain Vercel Node.js functions.
- Added api/handler.js as one explicit Vercel function.
- Updated vercel.json so /api/:path* is rewritten to that handler while preserving the original Express route path in the `path` query parameter.
- Kept the existing Express server routes, React app, and Vite SPA fallback.

Deploy
1. Extract this ZIP.
2. Copy the project files into the root of your existing GitHub repository (do not upload node_modules or any .env file).
3. Commit and push to the same production branch used by Vercel.
4. Wait for the deployment to finish.
5. Test /api/health, /api/products, and /api/admin/products.

Expected checks
- GET /api/health should return 200.
- GET /api/products should return 200 if MongoDB is configured and reachable.
- GET /api/admin/products without a valid admin session should return 401 (not Vercel 404). After admin login it should return the products list.

Keep existing Vercel environment variables. Do not upload server/.env or any credentials to GitHub.
